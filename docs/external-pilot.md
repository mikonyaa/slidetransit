# Fresh export and independent deck review

Status: **not performed for this local candidate**. Saved authored exports and new
synthetic PDFs provide separate mechanism evidence. An installed app, a script
passing its own tests, or a historical fixture is not today's export/review evidence.
This runbook requires a real deck, an operator who can export it, and a reviewer
independent of the implementation. No person is contacted by these scripts.

1. Choose a real deck you can share locally for review. Record the original PPTX
   SHA-256 before opening it. Fix the slide range, hidden-slide inclusion and order.
   Record the actual OS/build/architecture, exporter name/version/build, installed
   font names/versions (or font file hashes), export settings and UTC export times.
   Do not auto-save changes to the original source. Keep unknown information unknown.
2. Export `reference.pdf` from that frozen source in the reference environment;
   independently repeat it as `repeat.pdf`. Export `candidate.pdf` from the same
   unchanged PPTX in the delivery environment. Record source hashes actually used
   for each export. If bytes differ, classify it as a documented source variant;
   do not claim same-source compatibility. Export slides, not notes/handouts.
3. If a difference is confirmed, fix a separate copy `fixed-source.pptx`, record what
   changed, and export `fixed.pdf` freshly. A changed source tests repair sensitivity;
   it is not proof of an unchanged-source exporter defect. If no difference exists,
   use an unchanged source/control and state that outcome without inventing a defect.
4. Copy `docs/pilot-context.example.json` to a new local `export-context.json` and
   replace the unknown fields with observations. Correct `slideRange`; retain export
   settings, font evidence, source-use records and reviewer/device status. The context
   remains a user declaration. Freeze supplied bytes using the installed RC Python:

   ```sh
   /absolute/consumer/venv/bin/python scripts/freeze_pilot_inputs.py \
     --source /absolute/fresh/source.pptx \
     --reference /absolute/fresh/reference.pdf --repeat /absolute/fresh/repeat.pdf \
     --candidate /absolute/fresh/candidate.pdf \
     --fixed-source /absolute/fresh/fixed-source.pptx --fixed /absolute/fresh/fixed.pdf \
     --context /absolute/fresh/export-context.json --out /absolute/new/frozen-pilot
   ```

   The freeze script creates bounded read-only copies, input hashes and three
   validated manifests. It renders nothing and attests nothing. Check
   `input-hashes.json` against each supplied file and retain that file unchanged.
   Byte changes during freezing fail the operation and roll back its owned output.
5. Run the installed CLI outside the source checkout. Always use a new output path;
   retain exactly one JSON stdout document, stderr and actual exit for each run:

   ```sh
   /absolute/consumer/venv/bin/slidetransit compare \
     --manifest /absolute/new/frozen-pilot/repeat.json \
     --out /absolute/new/pilot-repeat --no-open --json
   /absolute/consumer/venv/bin/slidetransit compare \
     --manifest /absolute/new/frozen-pilot/candidate.json \
     --out /absolute/new/pilot-candidate --no-open --json
   /absolute/consumer/venv/bin/slidetransit compare \
     --manifest /absolute/new/frozen-pilot/fixed.json \
     --out /absolute/new/pilot-fixed --no-open --json
   ```

   Expect no serious repeat finding only when the measured channels actually support
   it; an unavailable text layer/native grid remains incomplete. Preserve unexpected
   results and investigate them. Keep all three comparison IDs, input/config/code/
   renderer bindings, full coverage rows, findings, crops and limits. Check that frozen
   input hashes are unchanged after every comparison. Do not tune thresholds to force
   a passing result; justify and bind any new configuration as a separate comparison.
6. The independent reviewer opens the self-contained `report.html` from `file://` with
   network/storage disabled, on a recorded real device/browser. Check both original
   exports and paired crops at 390/1024/1440 or applicable real-device sizes; use
   keyboard, filters, overlay only where available, zoom and side switch. On real slides,
   record which findings are valid, ambiguous or false alarms and which channels could
   not be measured. Record the reviewer's role, date, device/OS/browser version, exact
   comparison ID and input hashes. Preserve screenshots and observations; assertions
   generated by the implementation do not substitute for this independent review.
7. Accept only inspected differences with an explicit reason; export decisions and run:

   ```sh
   /absolute/consumer/venv/bin/slidetransit apply-review \
     --report /absolute/new/pilot-candidate/report.json \
     --decisions /absolute/review/review-decisions.json \
     --out /absolute/new/pilot-reviewed --no-open --json
   ```

   Accepted evidence must remain; incomplete required coverage must remain incomplete
   (exit 3 if no open finding is at threshold). Applied and stale decisions must be
   distinguished. Never rebind an old decision to the fixed report. Package hashes,
   export/review context, frozen inputs, original/reviewed reports, decisions, stdout/
   stderr, screenshots and the independent review note form the pilot evidence set.

The current CLI uses PPTX as source context; exported PDFs are the measured inputs.
This runbook adds no PowerPoint automation, cloud service or PPTX rendering engine.
Native worker/time/pixel limits are not an OS memory sandbox. General Office parity,
physical-device compatibility and a 10/10 assessment remain unconfirmed until actual
external records support them.
